# MCP Design

## Principle

MCP exposes typed AgentDock domain operations, not shell access.

The TypeScript bridge is intentionally thin:

~~~text
AI host
  |
stdio MCP
  |
@agentdock/mcp-server
  |
loopback AgentDock API
  |
agentdockd
  |
registry / port manager / proxy
~~~

Authorization and lifecycle policy remain in the Rust daemon.

## Current SDK

The server uses the MCP TypeScript v2 package:

~~~text
@modelcontextprotocol/server
~~~

with Zod v4 schemas.

## Implemented tools

### agentdock_status

Read-only daemon/proxy/registry health.

### list_services

Read-only service inventory including lifecycle, project, framework, port, and agent attribution.

### get_project

Read-only lookup by stable project ID or project name.

### list_routes

Read-only stable localhost route inventory.

### reserve_port

Reserves a free local port for the current MCP session.

The owner token is generated by the bridge, not supplied by the model.

### release_port

Releases only a reservation owned by the same MCP session.

### get_preview_url

Returns the project's stable local preview URL.

### cleanup_orphans

Inventories orphaned services.

Destructive execution is deliberately disabled. A non-dry-run request returns an error until process/session ownership can be proven.

## Not exposed

- arbitrary shell execution
- arbitrary filesystem reads
- kill-by-name
- killall
- unrestricted process termination
- environment-variable dumping
